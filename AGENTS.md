# AGENTS.md: guide for AI agents working on this repo

Read this before changing anything. It explains how the project is put together, the rules that keep it working, and the traps earlier agents already fell into.

> **Rule for every AI agent:** when you finish a piece of work in this repo, add an entry to the [Agent log](#agent-log) at the bottom of this file: a timestamp, who you are, what you changed, and why. Also update any section above the log that your change made out of date. See [How to write a log entry](#how-to-write-a-log-entry).

---

## 1. What this is

An HCI class project: a rebuild of SLU's Courses@SLU class search (originally a Leepfrog CourseLeaf "FOSE" site) running on **fake data**, plus usability improvements. `README.md` is for humans; this file is for agents. `TIMELINE.md` is the build plan and phase status.

- No real SLU data, no real logins. Every instructor, room and enrollment number is generated.
- Do not scrape or call SLU's live site or API.
- Not affiliated with SLU. Keep the "class project, sample data" label in the top bar.

## 2. Run, test, build

Node 20.19+ (developed on Node 22).

| Command | What it does |
|---|---|
| `npm install` | Install everything (one root `package.json`, no workspaces) |
| `npm run dev` | API on :3001 (`node --watch`) + Vite on :5173 (proxies `/api`) |
| `npm test` | `node --test` on `server/test/*.test.js` and `client/src/*.test.js` |
| `npm run seed` | Regenerate `data/db.json` from the hand-written data files |
| `npm run build` then `npm start` | Production: Express serves `dist/` and the API on `PORT` |

Before you say a change works: run `npm test`, run `npm run build` (then delete `dist/`), and check the change in a browser at desktop (≥1251px), medium (901–1250px) and phone (375px) widths.

## 4. Data model

`db.json` = everything in `reference.json` + `courses` + `sections` + `users`.

- **Course:** `code` ("CSCI 3300"), `subject`, `number`, `title`, `credits`, `courseType`, `prereqs` (codes), `core` (uuc attr codes), `flags` (core flag codes), `attrs`, `description`, `restrictions`, `typicallyOffered`.
- **Section:** `crn` (5 digits, unique across all terms), `term` ("202720"), `courseCode`, `section` ("01", "M01" Madrid, "OL1" online, "L01" lab, "P01" professional studies), `type` (LEC/LAB/SEM/ONL), `status` (A open, F full, C canceled), `campus` (code), `method` (P, OA, OS, HY), `session`, `instructor`, `meetings`, `startDate`, `endDate`, `credits` (labs attached to a lecture are 0), `capacity`, `enrolled`, `waitlistCap`, `waitlisted`, `attrs`, `linkedCrns` (lecture <-> lab), `restrictions`, `notes`.
- **Meeting:** `{ day, start, end, room?, building? }`. **`day` 0 = Monday ... 6 = Sunday** (same as the real API, not JS `getDay()`). Times are `"HHMM"` strings.
- **Term codes:** `YYYYTT`, YYYY = academic year end, TT 10 Fall / 18 Winter / 20 Spring. Fall 2026 = `202710`. Default term is Spring 2027 (`202720`).
- **User:** one demo student (`/api/me`), with `taken` course codes used for "Taken" badges and prereq check marks.

The seed is **deterministic** (seeded RNG). CRNs stay the same on every run, which keeps saved links working. If you change the generator or `courses.json`, CRNs may shift: say so in your log entry. The seed guarantees no instructor or room is double-booked, and it validates every reference (prereqs, subjects, campuses, attrs). Keep those checks passing.

## 5. Front-end architecture (read before touching App.jsx)

**The URL is the source of truth for what is on screen.** Every action calls `navigate()`; effects in `App.jsx` read the URL and load data. Don't keep "which view is open" in React state.

| URL | Screen |
|---|---|
| `/` | home: search form + welcome card |
| `?term=202720&q=...&subject=...` | search results (criteria keys match `/api/search` params) |
| `...&code=CSCI+3300&crn=20280` | plus the details panel for that course/section |
| `?term=202720&view=cart` | own primary cart (list) |
| `?term=202720&view=cart&cal=1` | own cart on the calendar (Primary Cart opens here by default) |
| `?term=202720&view=cart&crns=20063,20074` | someone else's cart shared as a link |

- Opening a different course **pushes** history (so Back closes it); switching sections of the same course **replaces**.
- The search form (`criteria` state) can differ from the URL until SEARCH is pressed. URL changes overwrite the form, and so do Back and Forward.
- Pressing SEARCH on an unchanged URL bumps `nonce` to re-run it.
- `runSearch` uses a request counter (`reqId`) so late responses from old searches are ignored.
- The cart lives in `localStorage` (`courseSearch.cart.<term>`), one list of CRNs per term; `useCart` syncs between components and tabs. Theme is `courseSearch.theme`. Always wrap storage in try/catch.

**Layout:** three panels (search 315px, results 350px, details/calendar the rest). `Slide` keeps a panel mounted while it slides out. The details panel and the calendar share the third slot. Responsive behaviour:
- **901–1250px:** the search panel hides while details or the calendar are open.
- **≤900px:** one panel at a time. The `view-results` and `details-open` classes on `.panels` decide which, and each step scrolls to the top except going back to the results list.

## 6. Conventions

- **Accessibility is a project goal, not polish.** Every control needs a label, and no `div` gets an onClick (use a `button`). Move focus into a panel's heading when it opens; Escape closes panels. Keep heading levels in order (h1 top bar, h2 panel titles, h3 inside panels, h4 detail bars). Re-run axe after UI changes; see the log for how. Target: zero WCAG 2.1 AA violations, light and dark.
- **Colors come from tokens** at the top of `styles.css`, with dark overrides in two places (the `prefers-color-scheme` media block and `:root[data-theme="dark"]`); keep them identical. Don't hard-code colors in components. Exception: calendar event fills are light in both themes, with dark text.
- **Respect reduced motion.** Animations use 1ms (not `none`) under reduced motion so `animationend` still fires.
- Keep the look of the original: SLU blue top bar `#003da5`, panel headers and buttons `#003b5c`, tan section bars (`--tan`, darkened for contrast), square uppercase full-width buttons, 14px system font.
- **Pure logic goes in plain `.js` modules with a `*.test.js` next to them** (`calendar.js`, `ics.js`). There's no React test runner; keep components thin.
- **API:** add routes in `server/app.js` and tests in `server/test/api.test.js`. Responses include display-ready fields (`meets`, `meetingLines`, `statusLabel`, `campusName`...) so the client doesn't need lookup tables.
- No new runtime dependencies without a reason in your log entry. Current runtime deps: express, react, react-dom, react-router-dom.
- **Git:** commit or push only when the human asks. Commit messages end with the co-author line the agent tooling provides. Line endings are LF (`.gitattributes`).

## 7. Known traps (already hit once; don't re-learn them)

- **`PORT` env var collision.** Preview tools set `PORT=5173` for Vite. The API therefore takes `--port=3001` from the dev script, and Vite has `strictPort`. Don't make the API read `PORT` first.
- **React StrictMode runs effects twice in dev.** Boot must not overwrite a term that came from the URL: `setTerm(cur => cur || default)`.
- **Store `defaultTerm` in boot state.** A bad `?term=` falls back to it; once it was `undefined` and only the server's own default hid the bug.
- **`Slide` must render in the same commit `show` turns on**, or refs for focus are null. It also unmounts on a 400ms timer as a fallback, because background or unfocused tabs throttle `animationend`.
- **Screenshots taken mid-animation look dim or shifted.** Check with `getAnimations()`/computed styles before "fixing" it.
- **Smooth scrolling is throttled in an unfocused preview pane.** Measure after a delay.
- **`node --test` on Windows/Node 22 needs file globs**, not a directory.
- **`.ics`:** `UNTIL` must be UTC; times use `TZID` with a `VTIMEZONE` block (Chicago, or Madrid for `campus === "MAD"`); fold lines at 75 octets.
